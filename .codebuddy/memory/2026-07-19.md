## 修复：多任务标注弹窗卡死（2026-07-19 续）
- **现象**：`pnpm tauri dev` 加载含 5000 图 / 6 份 COCO json 的目录时卡死，停在「找到 5000 张图片，6 个标注」，弹窗不出。

## 修复：选中巨型 COCO json 后导入阶段仍卡死（续）
- **现象**：弹窗能弹、能选，但选完 `instances_val2017.json`（≈200MB+）后导入阶段主线程被 `JSON.parse` 卡死，UI 无响应。
- **根因**：`importCoco` 直接在主线程 `JSON.parse(await jf.getText())` 解析 200MB 巨 json，V8 解析 + 建对象图阻塞主线程数秒甚至 OOM，UI 永久无响应。
- **修复（Worker 离主线程解析）**：
  1. 抽出纯函数 `importers/cocoTransform.ts`：`transformCocoData(data, path, registry)` + `cocoSplit`，**不碰 getBytes/文件 IO**，Worker 与主线程内联路径共用，单一逻辑来源。前者含原 `CocoImage/CocoAnn/CocoCat` 接口与分割/关键点/RLE 变换。
  2. 新增 `importers/cocoImport.worker.ts`：接收 `{id,path,text}`，`JSON.parse` + `transformCocoData`（Worker 内自建 ClassRegistry），回传 `{samples, classes, warnings}`（plain 可结构化克隆对象）。
  3. 新增 `importers/cocoImportClient.ts`：单例 Worker + reqId 映射 + `parseCocoInWorker(path, text)`；`worker.onerror` 时 reject 全部在途。实例化沿用项目既有 `new Worker(new URL('./x.worker.ts', import.meta.url), {type:'module'})` 模式。
  4. `importCoco` 重构：巨型 json（`>5MB` 且 `typeof Worker !== 'undefined'`）走 Worker（主线程仅异步 `getText` 不阻塞，仅 parse 在 Worker）；小文件内联解析。多份标注文件**按类别名合并**到主 `ClassRegistry` 并重映射 `annotation.classId`，主线程回填 `getBytes`（图片字节始终留主线程 VirtualFile）。`LARGE_JSON_BYTES=5MB` 阈值。
- **为何不用 getBytes(number[]) 传 Worker**：Tauri `read_file_bytes` 返回 `number[]`（每字节一个数），200MB 会膨胀成 ~6 亿长度的数组过 IPC，灾难性；改传 `getText()` 文本字符串（读取本身异步不阻塞，仅 parse 是 CPU 重活，已在 Worker 执行）。
- **验证**：`vue-tsc --noEmit` 仅 `ann.worker.ts` 既有报错（无关）；`vite build` 成功并产出 `cocoImport.worker-*.js`（Worker 打包正常）。`pnpm tauri dev` 下加载 val2017 选 json 后 UI 不再卡死（parse 在 Worker，主线程有进度）。
- **遗留**：200MB 文本过 IPC + 结构化克隆仍有内存/传输开销（单次，远小于原 6 份全量读+主线程 parse）；若仍偏慢，后续可在 Rust 端做预筛/流式解析。图片 `getBytes` 仍按需在主线程读取（仅渲染时）。
