## 修复 X-AnyLabeling 互操作：4 点矩形被读成线 + 导出缺字段"识别错误"

- 修复：
  - `types.ts`：`CanonicalAnnotation.raw?`（原始 shape 对象）、`CanonicalSample.rawTop?`（原始顶层 json，去 shapes）。
  - `importers/labelme.ts`：rectangle/rect/line 改为取**全部点** min/max 包围盒（4 点或 2 点都正确）；新增 `rotated_rectangle`(4 角点)→obb（cx,cy,w,h,rotation）；逐 shape 存 `raw`，样本存 `rawTop`。
  - `annotationIO.buildLabelMeContent`：写完整 X-AnyLabeling 结构（保留原始 version/flags/imageData/description，补 checked）；逐 shape 先展开 `raw` 再覆盖 label/shape_type/points，保留 group_id/attributes 等；矩形按原始 4 点/2 点约定回写（4 点＝TL,TR,BR,BL），obb→`rotated_rectangle` 4 旋转角点（与 `loadCanonical.obbCorners` 次序一致，无损往返）。
  - `canvas/canvasDraw.ts`：bbox 若 w=0 或 h=0（线标注）改为 `lineTo` 画线段，避免不可见。
  - `annotationParser.ts.parseLabelMe`（旧管线）：同样的 4 点矩形 min/max 修复 + rotated_rectangle 近似包围盒。

## 修复画框只能在已有框内/空白图无法画
- 症状：图像一个标签都没有时完全画不出新框；有框时「只能在已有框里/附近画」，框外空白区起笔无效。
- 根因：`ImageViewer.vue` 的 `onGestureUp` 里 `finishDraw(file)` 被包在 `if (file && idx >= 0)` 分支内（`idx=selectedAnnotationIndex`）。draw 模式起笔（onMouseDown 649 行）不改选中态，故只有「已选中某个已有框」时抬手才会创建新框；空白图 idx 恒为 -1 → 永远不 finishDraw。
- 修复：把 `mode === 'draw'` 独立成 `if (file && mode === 'draw') { finishDraw(file) } else if (file && idx >= 0) { ...编辑提交... }`，绘制新框不再依赖已选中标注；删除 idx>=0 块内已死的旧 draw 分支。`vue-tsc` 0 错误通过。
- 兼容确认（回答用户「是否影响其他通用格式」）：X-AnyLabeling 互操作的改动全部隔离在 labelme 导入/导出/parseLabelMe 专属路径，或纯新增可选字段（raw/rawTop）；唯一全局改动是 canvasDraw 用严格 `w===0||h===0` 判定退化框，正常框零影响。YOLO/COCO/VOC/DOTA/标准 LabelMe 不受影响。

## 修复画框预览/创建完全失效（onGestureMove 被 idx<0 提前 return 拦截）
- 症状：客户端与浏览器端都画不出框；选「画框」后光标变十字（editingMode 已生效），但拖拽时没有任何框预览，松手也不生成标注。Tauri 日志桥 `debug/browser.log` 实测确认：`[DRAW-DEBUG] mousedown -> draw branch`（正常）、`gestureup mode=draw`（正常）、但 `finishDraw w=0 h=0`（异常）。
- 根因：`ImageViewer.vue` 的 `onGestureMove` 在 `dragMode==='draw'` 时仍先执行 `const idx = selectedAnnotationIndex.value; if (idx < 0 || !anns[idx]) return`——而 draw 模式起笔不改选中态，`idx` 恒为 -1，于是函数提前 return，**永远走不到 `drawCur.value = norm`**，导致 `drawCur` 始终等于 `drawStart`，`finishDraw` 算出 `w=h=0` 被误判为「误点」丢弃。
- 修复：在 `onGestureMove` 的 `idx` 检查**之前**提前处理 draw 模式（直接 `drawCur.value = norm; renderImage(); return`），移除原 `else if (dragMode==='draw')` 死分支。四处 `[DRAW-DEBUG]` 诊断日志已清理干净。`vue-tsc` 仍 0 错误（仅 cBBoxToP/unflatten 未使用既有 HINT）。
- 经验：画框功能依赖「mousedown 进 draw 分支 → onGestureMove 持续更新 drawCur → onGestureUp finishDraw」，其中任何一环不触达 draw 分支都会静默失效；`selectedAnnotationIndex` 在 draw 模式下为 -1，所有 draw 路径都不能以「已选中标注」为前置条件。

## 修复画框轨迹/落点消失（renderAnnotations 空图提前 return 吞掉预览）
- 症状：画框时没有轨迹追踪、鼠标焦点上看不到落点；但第一击进了 draw 分支、rAF 循环在跑、drawCur 坐标实时变化（日志桥 [DR2] 实证：mousedown1 anchored=true、raf tick 连续、move 坐标递增 0.11→0.25→0.46→0.64→0.80）——链路全通却静默不显示。
- 根因：`renderAnnotations` 顶部 `const anns = annotations.value; if (!anns.length) return`（约原 330 行）对**空图**（当前图无任何已有标注，画框最常见场景）直接 return，而 `drawDrawPreview`（含第一击锚点十字 + 橡皮筋轨迹 + 尺寸标签）在该 return **之后**才执行，被整体短路。标签数量来自侧栏内存数据、与此无关 → 照常显示。
- 修复：改为 `if (!anns.length && !(store.editingMode.value==='draw' && dragMode.value==='draw')) return`——draw 预览态下即使 anns 为空也继续走到 drawDrawPreview；其余绘制（forEach 对空数组无害）不受影响。
- 排查手法：用限频临时 `[DR2]` 日志（第一击/raf 心跳前 3 次/move 每 25 次）让用户复现后从 `debug/browser.log` 读真实执行路径，三处全通即可断定是"绘制被吞"而非"事件/坐标未触发"。定位后已删除全部临时日志。`vue-tsc` 0 错误（仅 cBBoxToP/unflatten 既有 HINT）。
- 经验：`renderAnnotations` 顶部「无标注即 return」类早退会把"不依赖已有标注的预览/overlay 绘制"一并短路；任何 preview 绘制都要放在该早退之后，或让早退条件排除预览态。
