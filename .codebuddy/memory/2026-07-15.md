## WebWorker 池 + IndexedDB 哈希/质量缓存（规模化落地）
- **背景**：原质量检查与哈希均为「单 Worker + 内存、无持久缓存」，万级图片串行且重跑/重开需全部重算。
- **WorkerPool（src/workers/workerPool.ts）**：通用池，默认并发度 `clamp(hardwareConcurrency,4,8)`（即 4-8 并行）。任务队列 + 空闲 Worker 分发；每个 Worker 同时仅一个任务，返回按任务 id 匹配；处理 `onerror`/postMessage 失败与 `destroy()`。哈希与质量各持一个池实例（不同 worker URL）。
- **IndexedDB 双层缓存（src/cache/idbCache.ts）**：
  - `hashes`(md5→感知哈希+尺寸) / `quality`(md5→QualityResult) / `statIndex`(`path::size`→md5) 三 store。
  - 主线程批量查 `statIndex`（`getStatMd5Batch`）+ 内容 `getHashBatch/getQualityBatch`：未改动文件「免读字节」直接命中（重跑/重开秒回）。
  - Worker 内先算廉价 MD5，以 md5 查内容缓存；命中跳过昂贵的图像解码（createImageBitmap+DCT），未命中计算并写回。跨路径同内容、重跑均复用。
  - 提供 `clearCache()`（未来可在设置里加「清空缓存」）。
- **接入点**：
  - `hash.worker.ts` / `quality.worker.ts`：加 MD5 + 缓存查/写（quality 用 `{...cached.result, fileId: id}` 覆盖归属）。
  - `hashEngine.ts` / `qualityEngine.ts`：改用 WorkerPool 并行 + statIndex 快速命中；`computeHashesForFiles`/`runQualityCheck` 签名不变。
  - `hashService.ts`：原本是「内联 CDN Worker」（拉 jsdelivr 的 spark-md5，离线/Tauri 不可用、单 Worker），改为委托 `hashEngine`，使「计算哈希」对话框也获得池+缓存且双端一致；`confirmComputeHashes` 传入 `() => cancelCompute.value` 取消判定。
  - `analyze.ts` 去重哈希任务补 `size` 字段，启用基于尺寸的缓存失效。
- 验证：`vite build` 通过（2313 模块，built in 17.15s），`hash.worker`/`quality.worker` 各自 ~11KB（含 spark-md5+idbCache）正常打包；lint 0 错误。运行时需在浏览器/TAURI 真实跑确认 IndexedDB 命中（dev 下 `indexedDB` 可用）。

## ⚠️ Cargo 编译 E0252：`write_text_file` 重复定义 + CRLF 坑（7-15 续11）
- **报错**：`error[E0252]: the name __cmd__write_text_file is defined multiple times`，指向 `fn write_text_file` 行。根因：早先用 `replace_in_file` 向 `src-tauri/src/lib.rs` 插入 `write_text_file` 时，旧 `delete_files` 的 `///` 文档注释 + `#[tauri::command]` 被遗留为孤儿，导致 `fn write_text_file` 身上挂了**两个** `#[tauri::command]`，tauri 宏各展开一次 → 符号重复。
- **关键坑（必记）**：`src-tauri/src/lib.rs` 是 **CRLF** 换行。`replace_in_file` 工具用 LF 的 `old_str` 会**误报成功但实际未替换**（不生效）。修 Rust 文件务必用 Python（`open(...,newline='')` 保留 `\r\n`）做精确子串替换，或确认工具支持 CRLF。
- **修复**：用 Python 删除孤儿 `/// 直接删除一批文件...\r\n/// 仅删除...\r\n#[tauri::command]\r\n` 三行，使 `fn write_text_file` 仅剩一个属性。重新 `pnpm tauri dev` 应通过。
