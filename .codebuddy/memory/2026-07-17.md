## P2 onnxruntime-web + Vite dev 冲突修复（2026-07-17，已二次修正）

- 配套：删除 `public/onnx/`；`scripts/copy-onnx-wasm.mjs` 改为废弃说明；`vite.config.ts` 保留 `optimizeDeps.exclude:['onnxruntime-web']`。
- 验证：`vue-tsc --noEmit` 0 错误；`vite build` 成功产出 `dist/assets/ort-wasm-simd-threaded.jsep-*.mjs`(46KB) 与 `*.wasm`(26.8MB) 及 `embed.worker`(416KB)。**用户已确认「计算特征 / 查找相似」E2E 通过。**

## P2 相似检索：布局 + 推理性能优化（2026-07-17）
- **布局根因**：`.viewer-main` 是横向 flex 容器（`display:flex` row），而 `SimilarityView` 根 `.similarity-view` 缺 `flex:1`，只按内容宽度收缩 → 全挤在左侧、没铺满。修复：`.similarity-view` 加 `flex:1; min-width:0; box-sizing:border-box`；`.sim-tabs` flex 撑满 + `:deep(.el-tabs__content/.el-tab-pane)` height 撑满 + 空态 `padding-top:8vh` 居中。（同类视图套嵌在 viewer-main 都需 flex:1。）
- **GPU 说明**：`embedModel.ts` 用 `executionProviders:['wasm']` = 纯 CPU（WASM SIMD），**不会自动用 GPU**。onnxruntime-web jsep 版理论支持 `['webgpu']`，但 Tauri WebView2 支持不稳定，需回退逻辑，故暂不默认改。
- **内存/CPU 优化**：`embedEngine.ts` 不再用通用 `defaultPoolSize()`（[4,8]，适合 hash/quality 轻量任务）。新增 `embedPoolSize()`：每个 embed Worker 各持一份 ONNX 会话(模型16MB+wasm运行时26MB)且单线程 wasm 推理为 CPU 密集，故按 `navigator.hardwareConcurrency`(最多半数核) 与 `navigator.deviceMemory`(≤4G→2,≤8G→3,else→4) 自适应收敛到 **1–4**，避免低配机(双核/4G)卡死。`vue-tsc` 0 错误。

## P2「降维&离群」二次卡顿 + 导入慢修复（2026-07-17）
- **真正卡顿源（非 Worker 计算）**：`onAnalyze` 在 Worker 算完回主线程后，对**全部 N 个点并发 `ensureThumb`**（= N 次整图 `getFileBytes` + 建 object URL），300 张这波主线程爆发即用户感知的「PCA 算完点 UMAP 卡死」。散点图只需坐标、不需缩略图，只有「离群 Top-20」列表+预览需要；改为只对 `topOutliers`（≤20）生成缩略图。
- **按钮冻结**：PCA/UMAP 单选 `el-radio-group` 与「分析」按钮在 `analyzing || embed.running` 时禁用；`onAnalyze` 加 `if (analyzing.value) return` 防重入。
- **导入 18s 主因**：浏览器导入 `runLoad`（`src/dataset/loadCanonical.ts`）逐样本 `s.getBytes()` 把**整张图字节读进内存**只为调 `parseImageSize`（只需头部 16~30 字节），300 张大图触发巨量内存分配+GC → 「脚本执行」~18s。改为 `src.slice(0, 256KB).arrayBuffer()` 只读头部切片（惰性、不加载整图），EXIF 极长/罕见格式解析不到再回退全量。Tauri 路径尺寸来自 Rust 扫描、本就不读整图，不受影响。
- `vue-tsc --noEmit` 0 错误。结论：导入期并无独立「缩略图生成」步骤，慢在主线程逐张读整图取尺寸；相似视图缩略图本就是懒加载（仅结果/离群项），已进一步收敛。

## P2 相似检索：特征计算补齐与 MD5/质量同款缓存（2026-07-17）
- **之前差距**：`embedEngine.runEmbedding` 无条件先 `getFileBytesBatch` 读**全部整图字节**再丢给 Worker 查缓存；而质量/哈希用 `statIndex(path::size->md5)` + 批量查结果在**主线程免读字节**直接命中。embedding 还没写 `statIndex`，二次重跑也救不了。
- **修复**：`embedEngine.runEmbedding` 改为与质量/哈希同款范式——① 主线程批量 `getStatMd5Batch` + 新增 `getEmbeddingBatch`（idbCache 同 `getQualityBatch`）预筛，已缓存文件免读字节+免推理直接命中；② 仅未命中文件才读整图发 Worker（Worker 内 md5 内容缓存兜底，并复用 statIndex 的 md5 省 MD5 计算）；③ 计算后回填 `statIndex`（`putStatBatch`），使「仅算过特征」的数据集二次重跑也免读字节。
- **次要性能点**：`useEmbeddings.findSimilar`/`analysisPoints` 原每次都 `getAllEmbeddings()` 全量游标扫 IndexedDB；改为内存 memo（`allEmbeddings()`，随 `version` 自增失效重载），多次检索/切换重算不再重复读盘。缓存命中数实时透出到 `status`（「已抽取 N（命中缓存 M）」/「完成：…命中缓存 M 张，已跳过计算」）。
- `vue-tsc --noEmit` 0 错误。结论：特征计算现在与 MD5/质量一样的双层缓存（stat 免读字节 + 内容寻址），浏览器端 WebGPU 比 Tauri 单线程 wasm 快属预期。

## 桌面端下载/导出「点了没反应」修复（2026-07-17）
- **根因**：Tauri v2 的 WebView 会**静默丢弃** `blob:` URL 的 `<a download>` 下载，且 `window.print()` 也不可用 → 桌面端点「导出 ZIP / 下载报表 / 版本清单 / 删除脚本 / 编辑后标注 ZIP」等全部无弹窗、无落盘。
- **修复**：新增统一 `src/fileSave.ts` 的 `saveFile(filename, data, opts)`——浏览器走原 blob 下载；Tauri 调 `@tauri-apps/plugin-dialog` 的 `save` 弹原生保存对话框（可选 filters），再经新增 Rust 命令 `write_binary_file(path, contents: Vec<u8>)` 写盘。`dialog:default` 权限已含 `allow-save`（无需改 capabilities）。
- 路由改造（全部改走 saveFile，异步化 + 调用处 `void` 包裹浮空 Promise）：
  - `src/dataset/exportBrowser.ts`（ZIP / 训练工程 ZIP）、`src/dataset/exportAnnotations.ts`（CSV/JSON）`downloadBlob` → await saveFile。
  - `src/report/reportHtml.ts` `downloadReportHtml` 改异步；`printReportHtml` 加 `env==='tauri'` 分支——桌面端不调 print，直接 saveFile 存 HTML（用户再浏览器「另存为 PDF」），修复 PDF 按钮无反应。
  - `src/dedup/report.ts` `downloadText`/`downloadJSON`/`downloadHashIndex`、`src/dataset/versionStore.ts` `downloadManifest`(`useViewerState.downloadVersion` 改 async await)、`src/dataset/annotationIO.ts` 浏览器 ZIP 分支，均改走 saveFile。
  - 调用点 StatsView/SimilarityView/DedupView/quality-report 的下载处加 `void`。
- **注意大小**：`write_binary_file` 的 `Vec<u8>` 经 IPC 以 JSON 数字数组发送（`Array.from(bytes)`），超大 ZIP（数十 MB）会偏慢但可用；如需更优可改 base64（`read_files_bytes` 已有现成编码）或 IPC 二进制通道。
- 验证：`cargo check` 通过（Finished dev profile）；`vue-tsc --noEmit` EXIT:0（零错误）。重启 `tauri dev` 后：导出/下载均弹原生保存框并可落盘。

## 白屏修复：useViewerState 的 TDZ（2026-07-17）
- **现象**：进入界面白屏，控制台 `Uncaught ReferenceError: Cannot access 'activePane' before initialization`（useViewerState.ts:510，createViewerState:518）。
- **根因**：`wsSignature` computed（原 505 行）引用了 `activePane`（549 行）、`syncByFilename`（555 行）等在其**之后**才声明的 ref；紧跟的 `watch(wsSignature, ...)` 在 setup 时立即求值该 computed（Vue3 watch 会先读一次 source 取 oldValue），触发 TDZ。
- **修复**：把 `wsSignature` computed + `watch` 整体下移到 `syncByFilename` 声明之后（约 555 行后）。要求：computed 内引用的所有 ref 必须在其声明之前才安全。验证 `vue-tsc` EXIT:0。
- **注意**：在 useViewerState 这类「先定义 computed、底部才用到依赖」的文件里，新增 computed 引用靠后的 ref 时，要把 computed/watch 放在所有依赖 ref 声明之后，否则易踩同类 TDZ 白屏。
