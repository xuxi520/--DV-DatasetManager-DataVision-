## BUG 修复：点击质量检查报 `DataCloneError: #<Object> could not be cloned` 且弹窗无法取消
- 根因：`useQuality` 的 `options` 是 `ref<Required<QualityOptions>>`，Vue 把 `.value` 包成 **reactive 代理**。质量检查把整个 `options` 直接 `postMessage` 给 Worker，结构化克隆无法克隆 Proxy → 抛 DataCloneError。
- 连带 bug：`useQuality.run` 原先只在成功路径 `running.value=false`；异常抛出后 `running` 永远为 true，进度对话框（`v-model="qualityRunning"`）卡死、点取消无效。
- 修复（`src/quality/qualityEngine.ts` + `src/composables/useQuality.ts`）：
  1. postMessage 时把 options 拷贝为纯对象 `{ ...options }` 再传，杜绝 reactive 代理入 Worker。
  2. `run` 用 `try/finally` 保证异常/取消都复位 `running`。
  3. 额外健壮性：监听 `worker.onerror`/`onmessageerror`，Worker 加载/执行失败时即时 reject 在途请求并抛错（不再静默卡死）；每次运行前重置 `workerError`。
- 验证：`vue-tsc --noEmit` + lint 均 0 错误。
- 通用教训（务必记住）：**绝不要把 Vue reactive 代理对象直接 `postMessage` 给 Worker**，必须先 `{...obj}` 或 `toRaw`/深拷贝成纯对象，否则 DataCloneError。任何会长时间挂起弹窗的状态（如 `running`）复位都要走 `finally`。
