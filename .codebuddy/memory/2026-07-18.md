## 导出 COCO 报 "Invalid array length" 排查（2026-07-18）
- 用户反馈导 COCO 数据集报 `Invalid array length`。排查结论：**错误不在导出器逻辑，而在 RLE mask 渲染守卫太弱**。
- 全代码唯一会抛该错的 `new Uint8Array(计算长度)` 是 `src/codec/rle.ts` 的 `decodeRle`（`total = h*w`，当 `size=[undefined,undefined]` → NaN → `new Uint8Array(NaN)` 抛错）；它只被 `src/canvas/canvasDraw.ts` 的 `drawRleMask`(渲染期) 调用。导出器(`toCocoAnn`)不解码 RLE。
- 根因：`drawRleMask` 守卫 `if (w<=0||h<=0) return` 在 `rle.size=[undefined,undefined]` 时 `undefined<=0` 为 false 而失效，放行到 `decodeRle` 抛错。COCO 常含 mask 标注，导出时查看器重绘当前图触发解码 → 用户感知为"导出失败"。
- 修复：① `canvasDraw.ts` `drawRleMask` 增加 `Array.isArray(rle.size) && length>=2` 及 `Number.isFinite` 判断；② `rle.ts` `decodeRle` 对 `size` 含 undefined/NaN/非法长度直接返回 `Uint8Array(0)` 兜底。`vue-tsc` EXIT:0、lint 0。
- **数据质量提醒**：若 mask 的 `rle.size` 为 `[undefined,undefined]`，说明该 mask 标注的 size 未填充（可能来自导入或编辑路径），导出 COCO 会得到 `size:[null,null]`。当前修复避免崩溃，但根因（size 何时丢失）可后续在导入/编辑路径核查。
- **各导出功能审查结论**：YOLO/VOC/DOTA/LabelMe/COCO/标注CSV-JSON/增强导出逻辑本身均健全（无非法数组构造）；唯一真实 bug 即上述 RLE 渲染守卫。
- **用户二次反馈**：数据增强导出也报了同一个 "Invalid array length"，修 RLE 后两者都不报了。→ 证实错误纯在**渲染层** `drawRleMask→decodeRle`（导出对话框打开时查看器后台重绘当前图触发），**导出逻辑从未中招**（`applyAugmentation` 只对原图画布 `drawImage`，mask 作 ParsedAnnotation 几何变换后随标注带走，从不解码 RLE）。导出逻辑无需继续排查。

- **实现**：

## P2-2 ANN 索引迁 Worker（2026-07-18 续，已落地）
- **需求**：避免上帝组件——把 HNSW 建索引（addItems ≈ O(N log N)）从 `useEmbeddings.findSimilar` 主线程迁到独立 Web Worker。
- **实现**：
  - 新增 `src/embed/ann.worker.ts`：持有 HNSW 内存索引（仅内存不落盘、按 version 失效重建），接收 `build`/`search`/`reset` 消息。`build` 拷贝 entries（**不 transfer**，保护主线程 embeddings 不被 neuter）；`search` 走 `searchKnn`+过滤 `excludeMd5`，返回 `score=1-distance` 的 hits。onerror 由客户端兜底。
  - 新增 `src/embed/annClient.ts`：主线程单例客户端，`new Worker(new URL('./ann.worker.ts', import.meta.url), {type:'module'})`，reqId 映射在途请求 + `worker.onerror` 拒所有在途；导出 `buildAnnIndex/searchAnn/resetAnnIndex/destroyAnnWorker`。
  - `annIndex.ts` 精简为共享类型 `AnnEntry`/`AnnHit` + 常量 `ANN_M/ANN_EF_CONSTRUCTION/ANN_RANDOM_SEED`（移除主线程 `buildAnnIndex`）。
  - `useEmbeddings.findSimilar`：退为协调者——`all.size>5000` 时 `await buildAnnInWorker(...)`（同版本构建在途复用 `annBuildPromise`，版本失效重建）→ `searchAnn`；小数据暴力、异常 `annBroken` 回退暴力。`reset()` 清 ANN 状态并 `resetAnnIndex()`；构建成功清 `annBroken`（重算可恢复 ANN）。导出 `destroyAnnWorker`。
- **vite.config.ts**：新增 `worker: { format: 'es' }`（本项目 Worker 均为 `type:'module'`；ann.worker 懒加载 hnswlib 会产生 code-split 子块，IIFE 默认格式不支持 code-split → 须 ES 格式）。`vue-tsc`/`vite build` 初次因默认 IIFE 报 `Invalid value "iife" for option "worker.format"` 失败，加 `worker.format:'es'` 后通过。
- **门禁全绿**：vue-tsc EXIT:0、read_lints 0、vite build ✓ built in 39.02s（dist 含 `ann.worker-*.js` 1.38kB + `hnswlib-*.js` 子块）。P2-2 已知限制（主线程卡 UI）消除。
- **结论**：主线程零阻塞建索引；`useEmbeddings` 仅协调，重活全在 Worker，上帝组件风险解除。
