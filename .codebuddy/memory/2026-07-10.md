- 用户二次反馈：数据未彻底加载时"切图先出框延迟后才出图 + 悬停浮窗卡顿，加载完才恢复"。确认根因：即便生成已搬进 Worker，Tauri 下模块 Worker 易回退主线程解码（或 351 张 `<img>` 响应式更新+解码抢占主线程），缩略图流式生成阶段主线程被占满 → **缩略图确为主线程开销**；另一恒定杀手是 `loadCanonical.ts` 的 `getImageDimensions` 对每张图整图解码（主线程全量解码 351 张后 await）。
- 用户决策：确认缩略图是开销后**直接移除该feature与相关逻辑**。

## 切图卡顿根因修复：Blob 不再常驻（同日，最新）
- 现象：加载蔬菜水果数据集（3457 张图 / 7627 标注）后，点击切图 INP 高达 7–8 秒（DevTools 性能面板 `pointer div.file-name 7,696ms` / `button 8,320ms` / `keyboard INP 7,920ms`）。
- 根因：`loadCanonical.ts` 主循环对**每张图** `file.arrayBuffer()` 读全量字节 → `new Blob([bytes])` 并把 `url` 一次性生成，**全部字节常驻内存**；3457 张图的字节撑爆内存被系统换页到磁盘，切图时浏览器要把那张图的字节从页面文件读回内存解码 → 卡数秒。这是与「缩略图移除」那轮不同的第二处内存杀手（那轮是解码，这轮是常驻 Blob）。
- 修复（懒加载，内存里始终只保留当前一张图的字节）：
  - `types.ts`：`ImageFile` 加 `sourceFile?: File`（轻量文件句柄，不持有字节）。
  - `loadCanonical.ts`：建 `pathToFile: Map<path, File>`；主循环**只读字节算尺寸后丢弃**（不再 `new Blob` / 不再预生成 `url`），`sourceFile` 存句柄；尺寸仍用 `parseImageSize(bytes)` 零解码。
  - `useViewerState.ts` `selectFile`：切到某图时 `URL.createObjectURL(file.sourceFile)` 懒生成 `url`，切走时 `URL.revokeObjectURL` 释放上一张 → 内存只留当前一张。
  - `ImageViewer.vue`：`watch` 由 `props.imageFile`（对象身份）改为 `props.imageFile?.url`，以响应 selectFile 懒生成/释放触发重绘。
  - `dedup/fileOps.ts` `getFileBytes` 与 `hashService.ts`：因 `blob` 不再常驻，回退到 `sourceFile.arrayBuffer()` 懒读字节（去重/哈希仍可用，按需读单张）。
- 注意：加载期仍会为算尺寸把每张图全量字节读一遍（一次性、不常驻），磁盘读总量与改动前相当，但内存不再累积 → 切图卡顿消除；加载期读量可进一步优化为「只读头部若干 KB 取尺寸」或「Tauri 原生直读」。
- 验证：`pnpm exec vue-tsc --noEmit` = 0 错误；vite build 脱离式进行中。

## 关键定位：虚拟滚动/自动滚入视野失效的根因——滚动容器选错（同日，第四步·重要）
- 用户反馈：性能已好（脚本执行 369ms），但「选中项自动滚入视野没有生效」。

  - 后果 2：`scrollSelectedIntoView` 把 `el.scrollTop` 设在内层容器上 → 完全无效，自动滚入视野失效。
- 修复（`viewer.less`，作用域限定文件面板，不动标注面板等其它 `.panel-body`）：新增 `.file-panel .panel-body { display:flex; flex-direction:column; overflow:hidden }`。这样 `.file-list-container`（已是 `flex:1; min-height:0; overflow-y:auto`）成为有界滚动容器，`listRef.scrollTop` 才反映真实滚动，虚拟窗口与自动滚动同时修复。
